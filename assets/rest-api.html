AFE Agent SDK — REST API

Endpoint surface after the session / volume / sandbox decoupling. Volumes become first-class; sandboxes become volume-aware ephemeral compute; sessions decouple from sandboxes and bind to a volume via their agent.

NEW added in this spec UPDATED existing endpoint, changed contract SSE server-sent events stream

What the API operates on. One new table, two updated tables.

sandboxes
Updated
idTEXT PKunchanged
providerTEXTunchanged
sandbox_refTEXTunchanged — native provider id
statusTEXTunchanged
volume_idTEXT FK NOT NULL→ volumes.id, ON DELETE RESTRICT (new)
subpathTEXT NOT NULLmounted at /home/daytona (new)
Mental model: every sandbox is (volume_id, subpath)-scoped. When a session runs, the sandbox uses subpath = agents/<agent_id>/home so all sessions of the same agent share HOME on the volume. A second mount at subpath = shared is always added read-only to /mnt/shared.

Volumes

Persistent storage, user-scoped. Fully new resource. Shape parallels Sandboxes.

/volumes
New resource
Resource lifecycle
POST /volumes Create — body {name, provider}. Returns the volume row. New
POST /volumes/provision Create + wait until status = "ready". Mirrors /sandboxes/provision. New
GET /volumes List — optional ?provider=daytona filter. New
GET /volumes/{id_or_name} Inspect — full row plus resolved provider_ref. New
DELETE /volumes/{id_or_name}?force=false Delete — 409 if sessions reference it; force=true cascades. New
File operations (mirror /sandboxes/{id}/files/*)
GET /volumes/{id_or_name}/files/tree?path=shared/ Browse the volume contents. New
GET /volumes/{id_or_name}/files/read?path=… Read any file on the volume (shared/, agents/, …). New
POST /volumes/{id_or_name}/files/edit Write — body {path, content}. Used to seed shared/. New
File ops are backed internally by a short-lived utility sandbox with the volume mounted. Caller sees a pure REST endpoint; no need to manage sandboxes to seed data.

Sandboxes

Stay public and CRUD-able. Every sandbox is now (volume_id, subpath)-scoped at creation.

/sandboxes
Updated
Resource lifecycle
POST /sandboxes Create — body now requires {provider, volume_id, subpath, …compute params}. Updated
POST /sandboxes/provision Create + wait. Same new required fields. Updated
GET /sandboxes List.
GET /sandboxes/{id} Inspect — now includes volume_id and subpath. Updated
DELETE /sandboxes/{id} Kill — sessions survive with current_sandbox_id = NULL. Updated
POST /sandboxes/{id}/stop Stop the underlying compute (volume preserved).
POST /sandboxes/{id}/start Start a stopped sandbox.
File operations
GET /sandboxes/{id}/files/tree Browse the sandbox filesystem (sees the mounted subpath at /home/daytona).
GET /sandboxes/{id}/files/read Read a file.
POST /sandboxes/{id}/files/edit Write a file (edit or create).
POST /sandboxes/{id}/files/upload Upload a file — body {path, content: base64}.
POST /sandboxes/{id}/files/delete Delete a file or directory — body {path}.
POST /sandboxes/{id}/files/rename Rename/move — body {path, new_path}.
GET /sandboxes/{id}/files/download Download a file as raw bytes (forwards content-type + disposition).
Invariant: every sandbox mounts exactly one volume at exactly one subpath at creation. For session-driven creation, subpath = agents/<agent_id>/home. Plus the implicit shared read-only mount on the same volume at /mnt/shared. Daytona does not allow hot-attach, so changing the volume mount means creating a new sandbox.

Sessions

No longer bound to a sandbox. Binds to a volume (via its agent). Sandboxes are provisioned lazily and auto-replaced on failure.

/sessions
Updated
Resource lifecycle
POST /sessions Create — body now requires {agent_id, volume_id}. No sandbox_id. No compute provisioned yet. Updated
POST /sessions/quick One-shot — now requires volume_id too. Updated
GET /sessions List.
GET /sessions/{id} Inspect — current_sandbox_id may be null between runs. Updated
GET /sessions/{id}/status Status.
GET /sessions/{id}/log Event log (paginated).
Messaging / runtime
POST /sessions/{id}/message Send a prompt — lazily provisions a sandbox if needed.
POST /sessions/{id}/resume Resume — works even after sandbox was killed (HOME persisted on volume).
POST /sessions/{id}/cancel Cancel the in-flight run.
POST /sessions/{id}/config Update session config (env, secrets, etc.).
POST /sessions/{id}/sandbox/exec Exec a one-shot command in the session's current sandbox.
SSE /sessions/{id}/events Server-sent events — tool calls, tokens, plus new sandbox_reattach.
Sandbox control (new)
POST /sessions/{id}/start-sandbox Pre-warm — provision the sandbox eagerly to hide first-run latency. New
POST /sessions/{id}/stop-sandbox Kill current sandbox; next run() provisions lazily. New
POST /sessions/{id}/reset-sandbox Kill current + provision a fresh one immediately. New
Lazy provisioning rule: session creation does not touch the provider. First /message or /resume probes the provider state and picks: use-as-is → start-stopped → reprovision. The same agents/<agent_id>/home subpath means the CLI finds its transcripts on disk and resumes via --resume <inner_session_id>.

Agents

Mostly unchanged. Delete now cleans up the agent's HOME on any volumes that carried its state.

/agents
POST /agents Create an agent definition.
GET /agents List.
GET /agents/{id} Inspect.
DELETE /agents/{id} Delete — additionally removes agents/<agent_id>/ from every volume this agent used. Updated

Health & Admin

Unchanged from current server.

ops

GET /admin/sessions All sessions (admin view).

New SSE Events

Emitted on /sessions/{id}/events in addition to the existing events.

events
New
sandbox_reattach — emitted before the first real event of a run when the session reprovisioned its sandbox transparently. Payload: {old_sandbox_id, new_sandbox_id}.
