`agent-sdk` is two things in one repo:

- A **Python SDK** (`agent_sdk.Agent`, `Sandbox`, `ApiClient`) for sending prompts to coding agents and streaming their replies.
- A **FastAPI server** that runs those agents inside isolated sandboxes — local subprocess, Docker container, Daytona, or Modal — and persists sessions so they can be resumed.

## Why it exists

Coding agents (Claude Code, OpenCode, Codex, Gemini, Cline, OpenHands, Goose) all speak the [Agent Client Protocol](https://github.com/agentclientprotocol/spec) but bring their own runtime requirements, credential models, and lifecycle quirks. `agent-sdk` gives you one interface across all of them, plus the durable session + sandbox layer needed to run them in production.

## What you get

- **One SDK, eight agents.** `claude`, `codex`, `opencode`, `gemini`, `cline`, `deepagents`, `openhands`, `goose`.
- **Four sandbox providers.** `unix_local` (host subprocess), `docker`, `daytona`, `modal`.
- **Durable sessions.** Submit a prompt, kill the server, restart, resume — the conversation continues.
- **Live streaming.** SSE events for tool calls, reasoning, text deltas, usage.
- **Volume management.** Per-volume file ops independent of any sandbox lifecycle.
- **Multi-replica safe.** Per-worker lease + cluster-aware admin make it run across N replicas.
