---
title: Credentials
description: "How agent + provider credentials flow."
---

`agent-sdk` follows a strict rule: **the server never injects its own credentials**. Every secret reaches the agent only because the SDK or session config forwarded it.

## Where credentials live

| Credential | Used by | Plumbed via |
|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | claude agent | `Agent(oauth_token=...)` or env on SDK side |
| `OPENROUTER_API_KEY` | opencode agent | `Agent(api_key=...)` or env |
| `DAYTONA_API_KEY` | daytona provider | server env (control-plane only) |
| `MODAL_TOKEN_ID/SECRET` | modal provider | server env (control-plane only) |

Agent credentials (`oauth_token`, `api_key`) are forwarded as env vars into the supervisor process inside the sandbox. They never get logged, never written to `session_log`, and are scrubbed by `redact_secrets`.

Provider credentials (`DAYTONA_API_KEY`, etc.) are control-plane only — they let the server provision/destroy sandboxes. They never enter the sandbox.

## Forwarding pattern

The SDK reads the standard env vars by default:

```python
import os
os.environ["CLAUDE_CODE_OAUTH_TOKEN"] = "sk-ant-..."

agent = Agent("worker", agent_type="claude", provider="unix_local")
# token is auto-forwarded
```

Explicit:

```python
agent = Agent(
    "worker",
    agent_type="claude",
    oauth_token="sk-ant-...",
)
```

Mixed secrets (multiple credentials):

```python
agent = Agent(
    "worker",
    agent_type="opencode",
    secrets={
        "OPENROUTER_API_KEY": "sk-or-...",
        "GITHUB_TOKEN": "ghp_...",
        "HUGGINGFACE_TOKEN": "hf_...",
    },
)
```

Anything in `secrets=` lands in the supervisor's env. The session row persists the secrets (encrypted at the Postgres level if you configure it).

## Credential refresh

Short-TTL tokens (GitHub installation tokens, etc.) can be auto-refreshed via a webhook on the recipe:

```python
agent = Agent(
    "worker",
    agent_type="claude",
    secrets={"GITHUB_TOKEN": initial_token},
)
# Server spawns a background task that POSTs to credential_refresh_url
# with credential_refresh_token as bearer, expects JSON:
#   {"contents": {"/abs/path": "<base64>"}, "next_refresh_at": <unix-ts>}
# Files are written atomically into the sandbox.
```

Set `credential_refresh_url` + `credential_refresh_token` on the recipe via `ApiClient.create_session()` body (not yet exposed on `Agent` constructor).

## What the server never does

- Never reads your `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` from its own env.
- Never adds default credentials to sessions.
- Never logs secrets — even on exceptions.

If `oauth_token` and `api_key` are both absent, the supervisor boots with no credentials and the agent will fail at first model call. That failure is yours to handle.
